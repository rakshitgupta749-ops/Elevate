# Product Requirements Document
## AI-Powered Role-Play Interview Practice Platform

**Version:** 1.0
**Status:** Draft

---

## 1. Overview

### 1.1 Problem Statement
People preparing for high-stakes conversations (interviews, appraisals, negotiations, pitches) rarely get to rehearse against a realistic, reactive counterpart. Reading tips or practicing with friends doesn't replicate the pressure, unpredictability, or persona-specific behavior of the real person they'll face (a skeptical CTO, a blunt CEO, a process-driven HR manager).

### 1.2 Solution
A role-play application where users select a persona (CEO, CTO, CLO, HR, Manager, Investor, etc.), define a scenario, and set a toughness level, then conduct a mock interview via **text or voice chat** with an AI that stays in character, adapts difficulty, and gives structured feedback afterward.

### 1.3 Goals
- Let users rehearse real conversations in a low-stakes, repeatable environment
- Simulate persona-specific behavior and adjustable difficulty realistically
- Support both text and voice modalities with the same underlying logic
- Provide actionable, structured feedback after each session

### 1.4 Non-Goals (v1)
- Not a general-purpose chatbot / assistant
- Not multi-user (no group interviews, no interviewer-vs-interviewer)
- Not a hiring/assessment tool for actual candidate screening (practice only)

---

## 2. Target Users
- Job seekers preparing for interviews
- Employees preparing for performance reviews / appraisals / promotion pitches
- Founders rehearsing investor pitches or board conversations
- Students preparing for case interviews / viva / panel discussions

---

## 3. User Flow

1. **Landing / Entry** — user opens app, sees "Start New Session"
2. **Role Selection** — pick persona: CEO, CTO, CLO, HR, Manager, Investor, Client, custom (user-typed role)
3. **Scenario Input** — free text: "I'm interviewing for a senior backend role" / "I'm asking my manager for a raise" / "Pitching Series A to a VC"
4. **Toughness Slider** — 1 (supportive/easy) to 5 (aggressive/adversarial)
5. **Mode Selection** — Text Chat or Voice Chat
6. **Pre-session Brief** (optional) — AI shows a 2-3 line description of who it's playing and what to expect
7. **Live Session** — turn-based conversation, AI in character, one question/response at a time
8. **End Session** — user ends manually, or AI naturally concludes the interview
9. **Feedback Report** — structured breakdown: strengths, weaknesses, specific moment call-outs, suggested improvements, overall score
10. **History** — past sessions saved, viewable/replayable, progress tracked over time

## 4. Functional Requirements

### 4.1 Persona Engine
- Predefined persona templates (CEO, CTO, CLO, HR, Manager, Investor, Client) each with:
  - Communication style (formal/casual, terse/verbose)
  - Focus areas (CTO → technical depth; CLO → risk/compliance; HR → culture fit/behavioral)
  - Default toughness behaviors
- Custom role support: user types any role, system generates a persona profile on the fly via LLM
- Scenario injection: user's free-text scenario merged into persona system prompt
- Personas must stay in character; must not break immersion unless user explicitly requests a pause/exit

### 4.2 Toughness System
| Level | Behavior |
|---|---|
| 1 | Encouraging, simple questions, hints if user struggles |
| 2 | Standard, polite, occasional follow-up |
| 3 | Neutral professional, realistic follow-ups, no hand-holding |
| 4 | Challenges answers, asks "why," pushes on weak points |
| 5 | Aggressive, interrupts, devil's advocate, rapid-fire, minimal warmth |

- Toughness affects: question difficulty, follow-up aggressiveness, tolerance for vague answers, interruption behavior
- Optional: dynamic escalation if user is performing very well

### 4.3 Conversation Engine (Text)
- Turn-based chat UI
- Persistent session state (conversation history, phase tracking)
- Typing indicators, message timestamps
- Ability to pause and resume a session

### 4.4 Conversation Engine (Voice)
- Real-time voice input (STT) → LLM → voice output (TTS)
- Persona-appropriate voice selection (tone/pace mapped to role and toughness)
- Push-to-talk or continuous listening mode (configurable)
- Live transcript shown alongside audio (accessibility + review)
- Interruption handling: allow AI to "interrupt" at high toughness levels (barge-in behavior)
- Fallback to text mid-session if voice fails/user prefers

### 4.5 Feedback & Scoring
- Post-session structured report:
  - Overall score (e.g., /100 or rubric-based)
  - Strengths (with quoted examples from transcript)
  - Weaknesses / missed opportunities (with quoted examples)
  - Specific tactical suggestions
  - Tone/confidence/clarity sub-scores
- Delivered as in-app report; exportable as PDF
- Optional: benchmark against previous sessions of the same scenario type

### 4.6 Internet Access / Real-World Grounding
- The persona should be able to ground questions or reactions in real, current information when relevant — e.g. a CTO persona referencing a recent CVE or a real framework's latest version, a CEO persona referencing the company's actual market/competitors, an Investor persona referencing real comparable valuations.
- **Trigger conditions:** only invoke web search when the question genuinely needs current/factual grounding (e.g. "compare X vs Y," "what's the market rate for this role," "how does this stack up against competitor Z") — not for every turn.
- **User-side use:** if the user references a real company, product, technology, or statistic in their answer, the evaluator can optionally fact-check it and note inaccuracies in the final report (e.g. "You cited a growth rate that doesn't match public figures").
- **Report-side use:** the end-of-session feedback report can include a "reality check" subsection — e.g. flagging where the user's claims were accurate/inaccurate, or where the persona's questions were benchmarked against real industry data.
- Search results must be summarized/paraphrased into the persona's voice — never dumped as raw search output, to preserve immersion.
- Must be latency-aware: web search only fires when needed, since it adds round-trip time (relevant mainly in voice mode).

### 4.7 Session History
- List of past sessions with role, scenario, date, score
- Ability to replay transcript
- Progress trends over time (e.g., score improvement per persona type)

### 4.8 Account & Data
- User accounts (auth), session storage tied to user
- Privacy controls: delete session/history, opt out of storing voice recordings

## 5. Non-Functional Requirements
- **Latency:** Voice round-trip (STT → LLM → TTS) target under ~2.5s to feel conversational
- **Reliability:** Session state must survive network drops (resumable sessions)
- **Privacy:** Voice recordings encrypted at rest; user can disable storage entirely
- **Scalability:** Stateless conversation nodes so sessions can scale horizontally
- **Observability:** Full tracing of every session for debugging persona drift and quality regressions

## 6. System Architecture

### 6.1 High-Level Components
- **Frontend:** Web app (chat UI + voice UI), mobile-responsive
- **Backend API:** FastAPI (or similar) — session management, auth, persona config
- **Conversation Orchestration:** LangGraph — manages session state machine
- **Observability:** LangSmith — tracing, evals, prompt regression testing
- **STT/TTS:** Whisper (or streaming STT provider) + TTS provider (e.g., ElevenLabs-class voice)
- **Storage:** Postgres (sessions, users, feedback), Redis (active session state/cache)
- **LLM:** Claude (persona generation, conversation, evaluation, feedback)

### 6.2 LangGraph State Machine

**State object:**
```
{
  role, scenario, toughness, mode (text/voice),
  conversation_history, turn_count, phase,
  live_eval_notes
}
```

**Nodes:**
- `persona_node` — generates in-character interviewer response
- `tool_node` (web search) — invoked conditionally when a question or user claim needs real-world grounding (comparisons, current facts, stats); results are paraphrased back into persona voice, never shown raw
- `evaluator_node` — silently scores each user turn, optionally fact-checks user claims against `tool_node` results (runs in parallel, doesn't affect character behavior)
- `difficulty_controller_node` — adjusts next-question difficulty/tone based on toughness + performance so far
- `end_detector_node` — determines natural interview conclusion or explicit stop
- `feedback_node` — runs after session ends, generates structured report from full transcript + eval notes + fact-check notes, including a "reality check" subsection

**Flow:** `persona_node` → (conditionally) `tool_node` if grounding needed → wait for user input (interrupt) → `evaluator_node` (parallel, conditionally calls `tool_node` to fact-check) → `difficulty_controller_node` → loop back to `persona_node`, until `end_detector_node` triggers → `feedback_node`

**Note:** `tool_node` calls are conditional/gated, not run every turn — this keeps voice-mode latency low and avoids breaking immersion with irrelevant lookups.

### 6.3 LangSmith Usage
- Trace every node execution per session for debugging
- Maintain eval datasets per persona (does CTO persona ask technical questions? does toughness=5 actually interrupt?)
- Run LLM-judge evals on: persona consistency, toughness calibration, feedback quality
- Use for prompt regression testing before shipping persona/prompt changes

## 7. Persona Prompt Template (example)
```
You are roleplaying as a {role}, {experience_level}, known for {trait}.
Scenario: {user_scenario}
Toughness level: {toughness}/5 — {toughness_behavior_instructions}

Rules:
- Stay fully in character at all times
- Ask one question at a time, wait for the answer
- React realistically: push back on vague/weak answers, acknowledge strong ones
- Do not break character unless the user explicitly asks to pause/exit
- Do not explain your reasoning or reveal you are an AI unless asked directly
```

## 8. Milestones (Suggested)

| Phase | Scope |
|---|---|
| M1 | Text chat MVP: role selection, scenario input, toughness, LangGraph persona engine, basic feedback |
| M2 | LangSmith tracing + eval pipeline, persona quality tuning |
| M3 | Voice mode: STT/TTS integration, live transcript, latency optimization |
| M4 | Session history, progress tracking, PDF export |
| M5 | Dynamic difficulty escalation, custom persona generation, polish |

## 9. Success Metrics
- Session completion rate (% of started sessions that reach feedback)
- Repeat usage rate (users doing 3+ sessions)
- User-reported confidence improvement (post-session survey)
- Feedback quality rating (thumbs up/down on generated reports)
- Voice mode latency (p50/p95 round-trip time)

## 10. Open Questions
- Should voice interruption (AI barging in mid-answer at high toughness) be in v1 or deferred — technically complex?
- Should there be a "panel" mode (multiple personas in one session) later?
- Do we need industry-specific persona variants (tech CTO vs. finance CTO)?
- Pricing model — free sessions with cap, or subscription?
